# Пара года — плей-офф

Сетка из 16 пар посеяна по первым 16 строкам qualification-results.json. Внешние матчи слева: 1–16, 8–9, 4–13, 5–12; справа: 3–14, 6–11, 7–10, 2–15. №1 и №2 встречаются только в финале. Все 16 фотографий находятся в images/couples; их сопоставление с ID пар — playoff-photos.json.

## Подключение базы

Применить **playoff.sql** в Supabase SQL Editor проекта mcnhjrssxrxautjecpxo. Миграция добавляет отдельные таблицы плей-офф и RPC; существующие голоса и бюллетени отбора не удаляются. Повторное применение сохраняет результаты и состояние турнира.

После применения открыть «Пара года / Плей-офф» под одобренной учётной записью администратора. Первый раунд находится в ожидании: нажать «Открыть 1/8 финала», когда пора начать голосование. Завершение раунда фиксирует победителей и числа голосов; следующий раунд снова ожидает отдельного открытия. При равенстве администратор выбирает одного из двух участников матча и подтверждает итоги. При отсутствии голосов в любом матче переход запрещён.

Пока SQL не применён, страница показывает полноценную сетку и фотографии с сообщением о подготовке голосования. Сохранение не имитируется локально. Этапы остальных номинаций не переключаются; отдельная вкладка плей-офф доступна и при закрытом отборе.

## Сохранение и права

Одобренный пользователь сохраняет ровно один выбор в каждом матче активного раунда одним атомарным вызовом. Можно изменить весь бюллетень до закрытия раунда. Гость, ожидающий/заблокированный пользователь и администратор не голосуют. Закрытые раунды и устаревшие версии защищены сервером. Прямые записи в таблицы запрещены; чужие бюллетени не раскрываются. До подведения итогов числа голосов видны только администратору. Итоговые числа фиксируются при завершении раунда.

Для телефонов сетка сохраняет симметричную форму и прокручивается внутри своего контейнера; вся страница по горизонтали не растягивается. Выбор доступен мышью, касанием и с клавиатуры.

## Проверки

- `node --test scripts/backend.test.mjs scripts/playoff.test.cjs scripts/migration.test.mjs`.
- Миграция дополнительно выполнена дважды в локальном PostgreSQL/PGlite; проверены роли/RLS, запрет чужих/неполных бюллетеней, устаревшие версии, равенство и полный путь до чемпиона.
- Playwright проверил настоящую HTML-страницу с тестовым Supabase: 16 карточек, соединения, сохранение/ошибки, смену аккаунта, роли, голосование в следующем раунде и экран 390px.
- Более широкий старый набор проверок имеет известные несоответствия: qualification.test.cjs ожидает 22 пары при существующих 23; presentation.test.cjs требует исключённые из разреженного checkout медиа. Эти части данных не менялись.

Прежние голоса по старой схеме «до трёх пар» не переносятся в матчи и не используются для определения чемпиона. Представление результатов «Пары года» возвращает победителя и финалиста только после завершения турнира.
