# Отбор пары года — этап 1

Активный backend — Supabase. Миграция `qualification.sql` применяется один раз в SQL Editor проекта; она добавляет отдельные таблицы и включает фазу `qualification`. Старые голоса в `votes` сохраняются.

Отбор содержит 22 пары из согласованного списка, включая Шурика и Стешу, Сашу Шамбасова и Иванчикову. Каталог основного этапа не переименовывается и не смешивается с отбором.

Обычные посетители видят только отбор. Для голосования нужен одобренный пользовательский аккаунт. Каждый бюллетень содержит ровно 16 разных пар; его можно заменить до завершения отбора. Сохранение выполняется атомарно функцией `save_couple_qualification_ballot`, а не последовательностью удаления и вставки. Браузер показывает успех только после ответа сервера. Локальное хранилище не используется вместо базы.

Администратор видит отбор, его текущие итоги и все основные номинации ниже. Администраторы не голосуют. Рейтинг учитывает только одобренные пользовательские аккаунты; заблокированные и ожидающие исключены. Черта после 16-го места — предварительная граница. При равенстве используется алфавитный порядок, а равенство на проходной границе отмечается отдельно. При отсутствии голосов победители не назначаются.

В админ-панели есть отдельный раздел **Итоги отбора пар**: таблица всех 22 пар с местом и количеством голосов, включая нулевые результаты. Раздел обновляется при открытии, по кнопке и вместе с автоматическим обновлением раз в 30 секунд. Он использует тот же подсчёт, что и итоговый блок под отбором. Возврат ведёт в меню админ-панели. При выходе из аккаунта администратора данные раздела очищаются; обычным пользователям он не доступен.

RLS позволяет участнику читать только собственный бюллетень, администратору — все бюллетени. Прямые изменения таблицы клиентом запрещены. RPC проверяет аккаунт, этап, количество, уникальность и принадлежность выбранных ID каталогу. Триггер `enforce_award_voting_stage` блокирует запись, изменение и удаление основных голосов на время отбора, включая запросы со старых вкладок.

Настройки этапа читаются из `award_stage` при загрузке и раз в 30 секунд. При ошибке подключения отправка отключена, сохранение не имитируется. Смена аккаунта очищает чужой выбор и повторно загружает собственный. При смене роли админа на обычного пользователя закрытые разделы скрываются.

Для следующего этапа сначала нужно зафиксировать 16 прошедших пар и подготовить каталог основной номинации. После этого владелец переключает `award_stage.phase` на `main`. Интерфейс откроет основные номинации; голоса отбора останутся в отдельной таблице. Само переключение сейчас не выполняется. Неактивный Firebase-адаптер получил ограничения интерфейса, но отдельное хранение отбора реализовано для действующего Supabase.

Проверка: `node --test scripts/qualification.test.cjs scripts/backend.test.mjs scripts/presentation.test.cjs`. Браузерная проверка охватывает 16 из 22, перезагрузку, смену выбора, ошибку сохранения, гостя/ожидание/блокировку/админа, закрытые маршруты, мобильный экран и переключение фазы. Серверная проверка выполняется в транзакции с откатом, без сохранения тестовых голосов.
